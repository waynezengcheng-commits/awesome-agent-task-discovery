# Agent Task Radar

从可验证的开源实践中，发现最值得交给 Agent 的工作。这个仓库不是“又一个 Agent 工具目录”：它把已经出现的能力与工作流，整理为可以评估、排序和复用的任务机会。

每张卡片回答四个问题：任务是什么、Agent 接手哪一环、为什么值得优先做、证据在哪里。来源链接指向 README 或实现代码；不把宣传文案当作事实。

## 任务发现框架

优先选择能形成可控闭环的任务：

```text
触发信号 → Agent 判断/执行 → 可验证结果 → 人工复核或安全边界
```

前端为每个机会计算透明的 `P0 / P1 / P2` 优先级与 99 分制参考分：

- **影响力**：安全、代码导航、浏览器执行、成本路由、数据检索等类别具有不同的基础权重。
- **可复用信号**：GitHub Stars 仅作为公开采用的弱信号，且有上限，绝不等于业务价值。
- **可审计性**：存在来源证据链接时加分。

这不是 ROI 预测，也不应替代访谈、成本测算、合规评审或用户验证。它的作用是将探索队列缩小到值得深入验证的任务。

## 网站能力

- 以任务、工作流、能力或作者进行模糊搜索。
- 按能力类别、技术标签、采用信号和收藏筛选。
- 默认按任务价值排序，也可按 Stars、创建时间或最近更新排序。
- 卡片展示适合 Agent 接手的环节、收益线索、来源与优先级；详情页保留证据和限制说明。
- 浏览器本地保存收藏；`/`、`⌘K` 或 `Ctrl+K` 可聚焦搜索框。
- 提交入口会生成 GitHub Issue 草稿，要求任务、执行闭环、可衡量结果与人工/安全边界。

当前种子数据来自原项目收录的公开 Agent/AI 实践。它们是“任务机会的证据线索”，而非对任何项目、性能、安全性或商业回报的背书。

## 本地运行

需要 Node.js 22 或更高版本。

```sh
npm ci
npm run dev
npm test
npm run build
```

技术栈：Vite、React、TypeScript。`npm run build` 会先校验和投影公开数据，再生成静态站点并执行发布审计。

## 数据、证据与更新

`src/data/projects.json` 是当前的原始证据数据集；前端将每条来源实践解释为一个可探索的 Agent 任务机会。`scripts/prepare-public-data.mjs` 生成安全的公开投影 `public/projects.json`，浏览器只读取这一同源静态文件，不携带 GitHub Token，也不读取扫描回执。

`npm run radar` 运行 GitHub 来源的补充发现与元数据更新。它有明确边界：搜索结果受 API 限制、候选数受运行预算限制、公开代码证据不等于生产可用。请先审阅自动生成的内容，再提升其任务优先级或对外作出结论。

## 提交任务机会

点击网站中的“提交项目”（该按钮将逐步更名为“提交任务机会”），或在 GitHub 创建 Issue。提交应包含：

- 可公开访问的证据仓库；
- 清晰的任务触发条件与预期结果；
- Agent 的执行/判断闭环；
- 可衡量的成功标准；
- 人工确认、权限控制或安全退出边界。

不要提交仅有“可以使用 AI”的宽泛想法。一个好条目应使团队能够判断：谁会受益、何时运行、结果如何验收、失败会怎样处理。

## 维护原则

- 证据链接优先指向固定提交版本。
- 明确区分作者自述、自动提炼与独立验证。
- 不将 Stars、演示性能或模型输出视为商业价值证明。
- 高风险动作必须保留人工确认、最小权限和可逆路径。
